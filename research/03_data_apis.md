# Market data APIs for Solana/Base/BSC memecoins, with focus on historical data for backtesting — endpoints, auth, pricing, rate limits, history depth, and the cheapest path to a 20k+ launch training dataset

## Executive summary

The single biggest finding: you probably should not buy an API at all for the first training run. A free, MIT-licensed HuggingFace corpus (Slinky21/Pumpfun_Memecoin_Corpus, 6.7 GB) already contains 798,430 pump.fun launches, 33.58M trades, and 26.9M pre-graduation bonding-curve snapshots at ~15s granularity over a continuous 39-day window (Jun 5 – Jul 14 2026), with labeled graduation outcomes and a quantified data-quality audit. That is 40x the 20k launches asked for, at $0. A second free HF dataset (Tr4m0ryp/trenches-pumpfun-forward-2026-08, 85,442 mints, 730,850 point-in-time observations at 75s cadence) works as a clean out-of-sample forward-validation set. Its weakness is regime coverage: both are ~1-2 months, so a model trained on them is single-regime. For full history, NoLimitNodes sells the entire pump.fun archive (genesis→now, ~14M mints, ~1.8B trades, ~38k graduations) as monthly Parquet bundles for $200/mo — download one month and cancel. Among live APIs for assembling this yourself, Solana Tracker is dramatically the cheapest: its /search endpoint accepts minCreatedAt/maxCreatedAt with limit=500, so you can enumerate historical launches by date (unique among the vendors tested — Birdeye's new_listing is capped at a 3-day window and pump.fun's own /coins listing caps out around offset 1000-10000), and /chart/{token}?type=1m plus /holders/chart/{token}?type=1m give you exactly the per-minute OHLCV + holder time series you want. ~100k requests covers 20k tokens end-to-end, which fits inside the €50/mo (~$55) Advanced plan's 200,000 req/mo in a single month. Birdeye is the next best at ~$99/mo (Starter, 5M CU) using OHLCV V3 (/defi/v3/ohlcv, up to 5000 candles/call, 60/90/120 CU tiered) — ~2.7M CU for 20k tokens — but it cannot enumerate historical launches, so you must source the mint list elsewhere. Two important negatives: Dune is effectively unusable for bulk minute OHLCV export (20k tokens x 1440 min x ~6 cols ≈ 173M datapoints ≈ 173,000 credits, versus 25,000 credits on the $399/mo Plus plan), and Flipside is dead — it sold its blockchain data business to SonarX, Flipspace ran through June 17 2026, and docs.flipsidecrypto.xyz now 301s to edisyl.com. DexScreener has no OHLCV endpoint whatsoever and is a metadata/liquidity/social source only; I verified every documented endpoint live and extracted the exact rate limits from its OpenAPI spec (60 rpm for profiles/boosts/orders/ads/metas, 300 rpm for pairs/tokens/token-pairs/search). GeckoTerminal's public API is free but hard-capped at 180 days of history (verified: a before_timestamp one year back returns HTTP 401 with an explicit upgrade message) and I measured it 429ing after ~11 rapid calls, consistent with its documented 30 calls/min. On pump.fun's own infrastructure: frontend-api.pump.fun is DEAD (Cloudflare 1016 / HTTP 530) — the live host is frontend-api-v3.pump.fun — and the genuinely useful free endpoint is swap-api.pump.fun/v2/coins/{mint}/trades, which has working cursor pagination (100/page, nextCursor+hasMore) that walks backward through a token's full trade history unauthenticated; I sustained ~3.6 pages/sec. Its sibling /v1/coins/{mint}/candles is limited to the 1000 most recent candles with no backfill parameter (I tested to/before/endTs/offset — all silently ignored), so it is useless for history. Finally, PumpPortal's "free websocket" is now only partly free: subscribeNewToken and subscribeMigration are free, but subscribeTokenTrade and subscribeAccountTrade cost 0.01 SOL per 10,000 events and require a funded key.

## Numeric parameters

- **pumpfun_graduation_base_rate** = `0.0063 (arXiv, Sep-Oct 2025, 4,338 of 655,770) to 0.0071 (Slinky21 corpus, Jun-Jul 2026, 5,689 of 798,430)` — Two independent sources one year apart agree within 13%. Use 0.007 as the prior positive-class rate. Any backtest strategy showing a hit rate materially above this without a corresponding filter that shrinks the candidate pool is leaking future information.
- **pumpfun_graduation_threshold_sol** = `~85 SOL (~$69,000 market cap in Sep-Oct 2025)` — Hard protocol-level threshold from the arXiv study; use as the terminal condition label in the bonding-curve phase.
- **median_time_to_graduation_seconds** = `264 (~4.4 minutes)` — From the arXiv study. Your entry decision window is SECONDS, not minutes. Feature buckets must be 1s or 15s for the entry model; 1m bars are already too coarse for the median winner.
- **dump_event_rate_among_active_tokens** = `0.9222` — 92.22% of tokens with sufficient trading activity exhibited a dump event (arXiv). Model exit/stop-loss as the default outcome, not the exception.
- **bonding_curve_base_balance_at_graduation** = `206,900,000 tokens` — Bitquery documents graduation to PumpSwap as Pool.Base.PostAmount == 206900000. Use as an exact, cheap on-chain graduation detector.
- **bonding_curve_progress_formula** = `progress_pct = 100 - (((base_balance - 206900000) * 100) / 793100000)` — Bitquery's documented formula. 793,100,000 = 1,000,000,000 - 206,900,000. NOTE: pump.fun Mayhem-mode tokens mint 2,000,000,000 supply, so this formula and any 1B-supply concentration math must be branched on supply — this exact bug corrupted 109,561 rows (12.7%) of the Slinky21 corpus.
- **pumpfun_program_address** = `6EF8rrecthR5Dkzon8Nwu78hRvfCKubJ14M5uBEwF6P` — Filter key for every pump.fun query across Bitquery, Dune decoded tables, and raw RPC log subscriptions.
- **pumpfun_standard_supply** = `1,000,000,000 (standard) / 2,000,000,000 (Mayhem mode)` — ATH market cap = ATH price x supply. Getting this wrong produces >100% holder-concentration values, which is the tell that your pipeline has the bug.
- **birdeye_ohlcv_v3_cu_tiers** = `60 CU for <=1000 candles, 90 CU for <=2000, 120 CU for <=5000` — Request 1440 candles (24h of 1m) in one 90-CU call rather than two 60-CU calls — 90 < 120. Always right-size count_limit to the tier boundary.
- **birdeye_txs_token_hard_cap** = `offset + limit <= 10,000; limit max 50` — Absolute ceiling on trades retrievable per token from Birdeye. Any token above 10,000 trades is silently truncated — a survivorship trap on exactly the tokens that matter.
- **geckoterminal_public_history_days** = `180` — Enforced with HTTP 401, not a soft cap. Bounds any free GeckoTerminal-based dataset to a rolling 6-month window.
- **geckoterminal_rate_limit** = `30 calls/min documented; measured first 429 at call ~12 of an unthrottled burst` — Pace at 2.0 s/call with jitter. A naive 30-in-a-row burst gets ~40% 429s.
- **geckoterminal_ohlcv_coverage_per_call** = `1000 minute candles = 16h40m per request` — Two calls cover a 24h post-launch window; three calls cover 48h. Use for call-count budgeting.
- **pumpfun_swapapi_trades_page_size** = `100 (limit=101 returns HTTP 400)` — Hard cap on swap-api.pump.fun/v2/coins/{mint}/trades. Budget ceil(trade_count/100) requests per token.
- **pumpfun_swapapi_measured_throughput** = `~3.6 pages/sec = ~360 trades/sec, unauthenticated` — Measured over 12 sequential pages (1,200 trades in 3.3s). Unofficial and unguaranteed — throttle to ~3 rps and implement 429/5xx backoff.
- **pumpfun_candles_max_limit** = `1000, most-recent-only, no backfill parameter exists` — limit=1001 returns 400. to/before/endTs/offset are all silently ignored. Rules out /v1/candles for any historical dataset.
- **dexscreener_rate_limits** = `60 rpm (profiles, boosts, orders, ads, community-takeovers, metas) / 300 rpm (pairs, tokens, token-pairs, search)` — From the OpenAPI spec. No rate-limit headers are returned, so you must self-meter with two separate token buckets.
- **solana_tracker_search_page_size** = `500 (100 when format=full)` — 20,000 launches = 40 requests. The cheapest historical launch enumeration available.
- **solana_tracker_holders_chart_cap** = `1000 most recent data points` — At type=1m that is 16h40m of holder history per call — one call covers the critical first ~16 hours.
- **dune_datapoint_formula** = `datapoints = max(rows * columns, ceil(total_bytes / 100))` — Use this to precompute export cost before executing. 20k tokens x 1440 min x 6 cols = 172.8M datapoints = 172,800 credits on Analyst (which includes only 4,000).
- **dune_export_credit_rates** = `1 credit per 1,000 datapoints (Free/Analyst), per 5,000 (Plus), per 25,000 (Premium); CSV by MB: 20 (Free) / 10 (Analyst) / 2 (Plus) credits per MB` — The 25x difference between Analyst and Premium rates means the optimal Dune tier depends entirely on export volume, not query count.
- **dune_default_datapoint_cap** = `250,000 per results call (override: ignore_max_datapoints_per_request=true)` — A guardrail against burning a month of credits in one call. Leave it ON; if you hit it, that is a signal you should not be exporting through Dune.
- **helius_credit_costs** = `RPC 1 / getProgramAccounts 10 / archival 10 / DAS 10 / Enhanced Transactions 100 / Mint API 100 / webhook push 1 / webhook CRUD 100 / Priority Fee 1` — The 100:1 ratio between Enhanced Transactions and plain RPC is the single most important number in Helius cost modeling.
- **helius_webhook_address_cap** = `100,000 addresses per webhook` — One webhook can cover an entire watchlist. Webhook CRUD costs 100 credits per call, so batch address updates rather than editing per-token.
- **helius_webhook_auto_disable** = `>=95% failure rate over 7 days (24 hours on free plans)` — Your receiver must return 2xx fast. Queue-and-ack, never process synchronously, or you will lose the stream.
- **moralis_ohlcv_cu_cost** = `150 CU per call` — Starter ($149/mo, 2M CU) = only ~13,300 OHLCV calls/month. Do not select Starter for a 20k-token backfill; Pro ($249/mo, 100M CU) is the real entry point.
- **bitquery_solana_archive_start** = `May 2024` — Hard floor on Bitquery's v2 Solana archive and combined datasets. Pre-May-2024 requires the V1 endpoint and is transfers-only.
- **codex_aggregated_bars_history_floor** = `unix 1753121580 (2025-07-21)` — Documented floor for aggregated token bars. Verify pool-level bars separately before paying $350/mo.
- **birdeye_subminute_retention** = `1s: 2 weeks. 15s/30s: 3 months. 1m and above: undocumented.` — If your entry model needs 1s bars, Birdeye gives you a 2-week rolling window only — you cannot backtest 1s entries over a year through Birdeye.
- **nolimitnodes_archive_scale** = `14M+ mints, ~1.8B trades, ~38,000 graduations as of 2026-04-29; bundles 6-15 GB/month tar.zst` — Implies a lifetime graduation rate of ~0.27% (38,000 / 14,000,000) — LOWER than both the 0.63% and 0.71% windowed figures, consistent with the Slinky21 observation that the graduation rate rose ~900x over its 39-day window as platform usage grew. Your base rate is strongly non-stationary; do not train on one window and assume it transfers.
- **slinky21_corpus_filters** = `Exclude top10_pct_suspect (1,486 tokens); exclude sol_price_missing (2,360,061 rows / 7.03%, ~20,300 whole mints); exclude sol_amount/(token_amount*price_sol) outside [0.01, 100] (1,136,321 rows / 3.38%); use *_corrected concentration columns (109,561 tokens / 12.7% affected)` — Four mandatory filters. The author states skipping the sol_amount consistency filter alone fully distorts a naive top-wallet ranking.
- **pumpportal_trade_stream_cost** = `0.01 SOL per 10,000 events; requires linked wallet funded >= 0.02 SOL` — At ~$95/SOL that is ~$0.95 per million events — cheap, but no longer free. subscribeNewToken and subscribeMigration remain free.
- **pumpportal_connection_rule** = `exactly 1 websocket connection; violations cause hourly-expiring bans` — An architectural constraint, not a suggestion. Multiplex all subscriptions over one socket.
- **pumpportal_trading_fees** = `0.5% per Local trade, 1% per Lightning trade, computed pre-slippage` — If routing execution through PumpPortal, this fee must be in the backtest cost model. Pre-slippage computation means realized fee percentage will differ from nominal.

- FLIPSIDE IS DEAD. Sold its blockchain data business to SonarX; Flipspace ended June 17 2026; docs.flipsidecrypto.xyz 301s to edisyl.com. Every tutorial and SDK reference you find is stale. Do not budget or code for it.

- PumpArchive (github.com/PumpArchive/PumpArchive, api.pumparchive.com) advertises a complete pump.fun archive with an API. Every endpoint returns 404 'Application not found'. The repo has 2 commits. It does not exist as a usable service.
- DexScreener has NO OHLCV endpoint. Not undocumented — absent. The io.dexscreener.com chart-bars path that some scrapers use returns 403 behind Cloudflare. Any plan that says 'get candles from DexScreener' is wrong at the architecture level.
- Dune cannot bulk-export minute bars. 20k tokens x 1440 min x 6 cols = 172.8M datapoints = ~173,000 credits, versus 25,000 on the $399/mo Plus tier. Dune also bills AFTER execution and explicitly refuses to give a per-query cost formula in advance — you can burn a month of credits on one bad query. Instrument the credit field on every response and add a hard circuit breaker.
- GeckoTerminal's 180-day free limit is enforced with a 401 mid-pagination, not at request validation. A backfill loop that walks before_timestamp backwards will succeed for months and then start returning 401 bodies that a naive client may parse as empty results, silently truncating your dataset at exactly 180 days.
- The Slinky21 free corpus has a whole-token NULL-price defect affecting ~20,300 mints (7.03% of trades), and it is FRONT-LOADED — peaking at 33.6%/45.3% null on Jun 9-10, the first days of the window. Naively dropping null rows removes a time-biased subpopulation and will make your model look like it learned a regime it merely lost data from.
- The Mayhem-mode 2B-supply bug is the canonical memecoin data bug: concentration percentages computed against a hardcoded 1B supply produce values above 100%. It hit 12.7% of the Slinky21 corpus. If YOUR pipeline computes holder concentration or market cap, branch on actual supply — do not hardcode 1,000,000,000.
- Graduation base rate is strongly NON-STATIONARY. It rose ~900x across the Slinky21 corpus's 39 days, and the lifetime NoLimitNodes ratio (~0.27%) is well below both windowed measurements (0.63%, 0.71%). A model trained on any single window will have a miscalibrated prior. Use time-ordered splits and recalibrate the intercept per period; never random-shuffle split.
- Birdeye /defi/txs/token silently truncates at offset+limit <= 10,000. The tokens that exceed 10,000 trades are precisely the successful ones you most want to study — this is survivorship truncation aimed at your positive class.
- Birdeye does NOT document 1-minute OHLCV retention. It documents 2 weeks for 1s and 3 months for 15s/30s, then says 'extended history' for the rest. Probe empirically on free CU before assuming you can backtest a year of 1m bars.
- Birdeye batch/multi endpoints require the $499/mo Business tier ('All other batch, multi/multiple APIs are available exclusively for the BUSINESS package and higher'; LITE/STARTER get only the multiple-price API). A cost model built on Starter plus batching is off by 5x.

- Helius Enhanced Transactions cost 100 credits per call versus 1 for plain RPC. Backfilling 1M parsed transactions consumes 100M credits — the entire $499/mo Business allowance. Use raw webhooks and DAS (10 credits) instead.
- Bitquery sells real-time and history as SEPARATE products. Subscribing to Scale ($239/mo) and expecting historical Solana OHLCV will fail — you also need the $210/mo Solana archive add-on. And archive/combined reject USD-denominated fields (Trade.AmountInUSD, Trade.PriceInUSD, Trade.Side.AmountInUSD, Trade.PriceAsymmetry) and Trade.Side.Account inside where: clauses, failing with 'no table can query DEXTradeByToken'. - Bitquery's Solana v2 archive starts May 2024. Anything earlier requires the V1 endpoint and is transfers-only, not DEX trades.
- Codex aggregated token bars bottom out at unix 1753121580 (2025-07-21). At $350/mo for Growth, verify pool-level depth on the free tier first.
- PumpPortal's 'free websocket' is now only free for subscribeNewToken and subscribeMigration. Trade streams cost 0.01 SOL per 10,000 events and need a wallet funded with >=0.02 SOL. A December 2024 PumpPortal tweet saying the Data API is free is stale — the current docs override it.

- Jupiter's api.jup.ag/price/v2 returns 404 and token.jup.ag/all no longer resolves. Use lite-api.jup.ag/price/v3 and lite-api.jup.ag/tokens/v2/*.
- DexScreener returns NO rate-limit headers. You must self-meter two separate buckets (60 rpm and 300 rpm) — there is no server feedback to back off on except the failures themselves.
- pump.fun /v1/candles accepts to, before, endTs, and offset parameters WITHOUT ERROR and ignores them, always returning the most recent N candles. A backfill loop using them will happily fetch the same 1000 candles thousands of times and produce a dataset that looks full and is entirely duplicated. Always assert that returned timestamps actually moved.
- Solana Tracker prices in EUR, not USD. Budget in EUR and account for FX.
- No provider tested offers per-minute HOLDER history except Solana Tracker (/holders/chart, capped at 1000 points). If your model needs holder-growth velocity — which the literature suggests it should — you have exactly one API option, or you derive it yourself from raw token-account state.
- GeckoTerminal and Solana Tracker OHLCV responses contain NO trade count. Only Moralis returns a per-candle trade count, and Birdeye returns counts only as current-snapshot frames. Since trade count is the denominator of the strongest published predictor (liquidity per trade), plan to derive it from raw trades rather than from any candle API.
- The median time-to-graduation is ~4.4 minutes. Building the entry model on 1-minute bars discards most of the signal for the median winner. Use 1s or 15s buckets for entry features — available free from raw trades, from Birdeye v3 (1s, 2-week retention), from Solana Tracker (type=1s), and from CoinGecko onchain (timeframe=second).

### That free corpus has four quantified defects that WILL silently corrupt your model if unhandled. The dataset author documents each with exact row counts.

(1) Mayhem-mode 2B-supply bug: concentration percentages were computed against a hardcoded 1B supply, producing initial_top10_pct up to 200%. Affects 109,561 tokens (~12.7%). FIXED — you must use the *_corrected columns (initial_top1_pct_corrected, initial_top5_pct_corrected, initial_top10_pct_corrected, dev_buy_pct_corrected, supply_bug_corrected). (2) Bonding-curve-balance leak: 1,486 tokens with impossible concentration (median top1_pct 98.8%, up to 129.3% at top10), concentrated in a Jun 23-24 clone/factory-launch burst; top1_pct correlates 0.71 with curve balance at first trade for affected rows vs -0.02 for unaffected. UNFIXABLE — flagged via top10_pct_suspect, must be EXCLUDED not imputed. (3) sol_amount inconsistent with token_amount * price_sol, off by up to ~39,000,000x: 1,136,321 rows (3.38% of 33.58M). Detect by flagging sol_amount / (token_amount * price_sol) outside [0.01, 100]; exclude from all SOL-denominated volume/PnL. The author confirms skipping this filter fully distorts a naive top-wallet ranking. (4) NULL sol_amount/price_sol: 2,360,061 rows (7.03%), flagged via sol_price_missing. Heavily front-loaded — peaks at 33.6%/45.3% null on Jun 9-10. It is a WHOLE-TOKEN phenomenon: of ~20,300 affected mints, >99.8% have every trade null-priced. Skews to early trades (median ~20 min post-launch vs ~2.4h corpus-wide).

**Actionable:** Hardcode these as ingestion filters: WHERE top10_pct_suspect = false AND sol_price_missing = false AND sol_amount/(token_amount*price_sol) BETWEEN 0.01 AND 100. Use only *_corrected concentration columns. Because the null-price defect is whole-token and front-loaded, dropping those rows silently drops ~20,300 tokens biased toward the first 10 days — either drop those mints entirely from the training set or add a date-of-launch control.
